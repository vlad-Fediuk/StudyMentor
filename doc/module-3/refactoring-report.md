## Збереження поведінки

Глобальний exception handler повертає `{ error, statusCode }`, тоді як старі локальні
CRUD-обробники повертали `{ error }`. Тому просте видалення catch змінило б контракт.
Новий фільтр зберігає стару форму і ловить ValidationException лише на create/update.
Несподівані помилки як раніше доходять до глобального handler.

Збереження вправ перенесене без зміни правил: trim, обрізання назв до 48 символів,
дедуплікація варіантів без урахування регістру, додавання відсутньої правильної відповіді,
fallback до другого варіанта й порядок елементів.
AppDbContext і міграції не змінювалися, тому структура БД не зачіпається.

## Перевірки та обмеження

Команда: `dotnet test StudyMentor.sln --settings coverage.runsettings --collect:"XPlat Code Coverage"`.
Контрактні HTTP-тести використовують реальні handlers/EF InMemory; тести persistence
ізолюють збереження через підставні CRUD-сервіси. Це не перевірка живого PostgreSQL,
pgvector або зовнішніх AI-провайдерів.

У поточній базі модуля не було тестових проєктів із початкового плану, тому додано
окремий StudyMentor.QualityTests. Із solution прибрано лише неробочі посилання
на відсутні сторонні dotnetlab5/dotnetlab7chat; файли на диску не видалялися.

Повторні метрики, категорії й висновки наведено в [sonarqube-report.md](sonarqube-report.md).

Фінальний прогін: 23 успішні тести; повторний скан містить той самий набір тестів і окремий файл покриття цього запуску.

Додаткова регресійна перевірка виявила конфлікт описів Swagger після версіювання:
JSON-документ повертав 500. Підключено версійований API Explorer, окремі документи
Swagger і native OpenAPI для v1/v2 та додано чотири HTTP-перевірки їхніх маршрутів.
Необхідне оновлення OpenAPI-пакета також усунуло попередження NuGet audit.
